# Nirav Hair Storm — Salon & Spa Billing System

A complete billing and salon-management web app built with **plain PHP 8 (no framework)** and **MySQL**. It ships its own lightweight MVC core — routing, database layer, templating, authentication, role-based permissions, CSRF protection, and dependency-free CSV/PDF export.

> **Note:** Invoice PDFs are generated by a self-contained PDF writer (`app/Core/PdfExport.php`) — no external libraries required.

## Features

### Dashboard
- Revenue summary cards (today, month, outstanding, customers, new bills)
- Interactive sales chart (Chart.js)
- Recent bills, top services, staff performance
- Customers with low package balance & inactive customers
- Activity feed

### Billing (POS)
- Create invoices in a single screen — search/add customers, add services, split a service across employees, apply packages & discounts, GST calculation
- Full invoice history with status filters (paid / partial / outstanding / cancelled) and pagination
- Invoice detail page, print-friendly view, and **PDF download**
- Record partial payments (cash / card / UPI / bank / other) and cancel invoices
- Auto-generated invoice numbers with configurable prefix

### Customers
- CRUD with photo upload, mobile/email, gender, DOB, address
- Internal notes log
- Package assignment / cancellation, per-package credit balance
- Per-customer invoice history and statement

### Packages
- Prepaid credit packages (selling price, credits, validity in days)
- Assign to customers, track remaining credits with a full transaction ledger (`purchase / credit / debit / adjust / expire`)
- Low-balance and expiry tracking

### Services
- Categorized service catalog with duration & price
- Active/inactive status

### Employees
- Staff directory with designation, photo, commission rate
- Per-employee profile: services performed and earnings

### Reports
- Revenue report, package sales, staff earnings, service totals, outstanding balances, customer statements
- Date-range filtering, print view, and CSV export

### Settings
- Business info (name, address, phone, email, GST, logo)
- Invoice configuration (prefix, footer, terms, default GST)
- Preferences (theme mode, default report range)
- Users & roles — custom role-based permissions per module
- Database backup (downloads a `.sql` dump), activity log viewer

### Auth & Access
- Login/logout, password change, session-based auth
- Role-based access control (RBAC) with per-module permissions
- CSRF token protection on all POST forms
- Full activity audit log (who did what, IP, user agent)

## Quick Start (Local)

### 1. Create the database

```sql
CREATE DATABASE nirav_hairstorm CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 2. Configure credentials

Credentials default to `root` / empty password on `127.0.0.1:3306` and can be overridden with environment variables (see [Configuration](#configuration)). Optionally copy `config/database.php` and set your own.

### 3. Run with the PHP built-in server

```bash
php -S 127.0.0.1:8000 -t public
```

### 4. Install

1. Visit **http://127.0.0.1:8000/install.php**
2. Set your admin name, email, password, phone and click **Install Application**.
3. The installer runs `database/schema.sql` + `database/seed.sql` and creates your admin account.
4. **Delete `public/install.php`** after installation.
5. Sign in at **http://127.0.0.1:8000/auth/login**.

> Default seeded data: 3 roles (Admin, Manager, Front Desk), 10 services, 5 packages, 6 employees, and default settings (business info, invoice prefix `INV-`, GST 18%).

### One-shot scripts

**Seed the database** (creates DB if missing, applies schema + seed, creates/updates the admin user — no need to visit `install.php`):

```bash
php scripts/seed.php                          # admin@salon.local / admin123
php scripts/seed.php owner@salon.com "mypass" # custom admin
```

**Run locally** (seeds, then starts the built-in server):

```bash
./scripts/serve.sh                  # http://127.0.0.1:8000
PORT=9000 ./scripts/serve.sh        # custom port
SKIP_SEED=1 ./scripts/serve.sh      # skip re-seeding
```

> If `pdo_mysql` isn't loaded, pass its ini directory:
> `PHP_INI_SCAN_DIR=/path/to/phpconf ./scripts/serve.sh`

## Configuration

Environment variables (set via your server/`.env` provider — no `.env` file loader is bundled; use the web-server env or `putenv` if needed):

| Variable      | Default                  | Description               |
|---------------|--------------------------|---------------------------|
| `APP_ENV`     | `production`             | `development` / `production` |
| `APP_DEBUG`   | `false`                  | `true` shows error details |
| `APP_URL`     | `http://localhost/salon` | Base URL                  |
| `DB_HOST`     | `127.0.0.1`              | Database host             |
| `DB_PORT`     | `3306`                   | Database port             |
| `DB_DATABASE` | `nirav_hairstorm`        | Database name             |
| `DB_USERNAME` | `root`                   | Database user             |
| `DB_PASSWORD` | *(empty)*                | Database password         |

Static config lives in `config/config.php` (app name, timezone `Asia/Kolkata`, currency `₹`, session name/lifetime, upload rules).

## Database Schema

15 InnoDB tables with foreign keys and indexes:

| Table                         | Purpose                                             |
|-------------------------------|-----------------------------------------------------|
| `roles`                       | Roles with JSON permission map (`{"*":true}` = admin) |
| `users`                       | Backend staff accounts (FK → roles)                 |
| `customers`                   | Customer profiles (unique mobile, fulltext name)    |
| `employees`                   | Staff (commission rate, designation)                |
| `services`                    | Service catalog (category, duration, price)         |
| `packages`                    | Prepaid package templates                           |
| `customer_packages`           | Package instances assigned to customers             |
| `customer_package_transactions` | Credit ledger per package (purchase/debit/expire) |
| `invoices`                    | Invoice header (subtotal, discount, GST, paid, balance, status) |
| `invoice_items`               | Line items (service, qty, amount)                   |
| `employee_allocations`        | Service split across employees per invoice item     |
| `payments`                    | Split payments (cash/card/upi/bank/other)           |
| `ledger_entries`              | Running customer statement of account               |
| `customer_notes`              | Internal notes per customer                         |
| `settings`                    | Key-value store (business info, invoice, theme)     |
| `activity_logs`               | Audit trail (user, type, description, IP, UA)       |

**Invoice status flow:** `draft → issued → partially_paid → paid` (or `cancelled`).

## Security

- **CSRF protection** on every POST form (token in session, validated in `Request`)
- **RBAC middleware** — routes declare `Permission::class, 'module.action'`; checked against role JSON
- **Password hashing** with `password_hash()` / `password_verify()` (bcrypt)
- **SQL injection** — all queries use prepared statements
- **XSS** — all output escaped via `e()` helper in views
- **File uploads** — MIME/extension whitelist, size limit (2 MB), served from `public/uploads`
- **Hardening headers** & `Options -Indexes` in `.htaccess`
- Root `.htaccess` blocks direct access to `app/`, `config/`, `database/`, `routes/`, `vendor/`, `uploads/`
- Session cookie `HttpOnly`, `SameSite=Lax`
- Installer must be deleted after setup
